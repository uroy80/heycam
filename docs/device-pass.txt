- Text models: a photo imported from the Photo Picker was read in Latin. Text → Language → Read again as Japanese
  made Play services install mlkit.ocr.japanese while Latin was loaded in heycam; heycam kept the same process and
  read the page. The same held for Devanagari (Latin and Japanese loaded), Korean (Devanagari loaded) and
  Settings → Download all languages (Chinese, the other four loaded: "Ready"). Adding a model did not restart
  heycam ("Module config changed, forcing restart" never appeared); updating a loaded one does (device tests,
  below). A real phone with other Play services versions stays on the list.
- Process death with the "Save to" picker open: export sheet set to Small, Letter, Narrow; Save; in the picker,
  adb shell am kill in.edgr.heycam; SAVE. heycam came back in a new process and wrote the file: 1 page, Letter
  612 x 792 pt, 60,297 bytes (the sheet said about 62 kB), PDF 1.7, the text layer read by pdftotext.
- 200% text on a 360 dp wide screen (wm density 480 on 1080 px, font_scale 2.0): Home and the export sheet have
  nothing clipped; the sheet's size and page-size choices stack and scroll, and Save, Share and Print are reached
  by scrolling. The file name field scrolls sideways.
- Landscape with the "tall" cutout overlay: Document (Pages and Text) keep clear of the cutout.
- Device tests, heycam_integrate_api37, after the changes of 0b60cf3 to 2e4ee47: connectedDebugAndroidTest 18/18

  So Play services does restart heycam when it updates a model heycam has loaded; pages left PENDING are read at
  the next start (or marked skipped when automatic reading is off).
